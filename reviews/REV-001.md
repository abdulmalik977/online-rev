### BLOCKING-1 — Replace the "hard-capped adapter" standard with a bounded practical adapter
Evidence: `run_agent.py` lines 71–76 require `*_METERED_COMMAND`; README "Quota and
scheduled execution"; BLOCKERS #3; approvals SETUP-QUOTA.
Decision (Claude, planner): provider quota cannot be hard-capped from outside; we bound it
by construction instead. Implement `scripts/adapters/claude_adapter.py` and
`scripts/adapters/codex_adapter.py` that:
- read the context on stdin and pass it as the prompt;
- invoke the non-interactive CLI with a turn cap derived from `COMPANY_MAX_CREDITS`
  (Claude: `claude -p --output-format json --max-turns N`; Codex: `codex exec --json`
  or equivalent — verify flags against the installed versions and record them in README);
- run under the existing `AGENT_TIMEOUT_SECONDS`;
- parse the CLI's own usage output and return `{"usage": credits, "summary": ...}` where
  **1 credit = 1 turn** (simple, observable, matches how both subscriptions throttle by
  activity); token totals go into the run log for later calibration;
- return nonzero if the CLI reports no usage (runner already treats that as failed with
  reservation retained).
Bound: ≤ 120 lines per adapter, one test each using a fake CLI. Reservation-before-launch,
80% reserve, and quarantine-on-breach logic stay exactly as built.
Resolve SETUP-QUOTA in approvals with this decision; provider-window throttling (5-hour
rolling) remains an accepted residual risk and is why runs are 2+3 per day, not continuous.

### BLOCKING-2 — Counters that loop detection depends on must be script-owned
Evidence: `grep -rn "review_round\|attempts" scripts/` — read in rules and validation only;
no writer. An agent that forgets (or chooses not) to bump `review_round` can loop forever
and rule 1 never fires; same for `attempts` and rule 3. Rule 2 (24h stale) is the only
backstop and it only flags.
Fix: add to `watchdog.py` two admission-style commands under the same writer lock:
- `--review TASK-ID --result pass|changes|reject --note "..."` → appends a REV-nnn entry,
  increments `review_round`, sets status `review`→`doing` (changes) or `done` (pass);
- `--attempt TASK-ID --note "..."` → increments `attempts`, touches `updated`.
Agent files (`agents/*.md`) then say: reviews and attempts go through these commands;
direct edits to the two counters are a protocol violation reported by the watchdog
(compare counters against the REV/attempt log lines it owns).
Bound: ≤ 80 lines + 2 tests (increment persists; 3rd review round triggers rule 1 on next scan).

### BLOCKING-3 — Stop committing mutable runtime state
Evidence: after one scan + one report + two dry runs, `git status` shows `db/company.sqlite`,
`logs/watchdog.json` modified and 3 new run logs. With a 30-minute cron this repo conflicts

Fix: `.gitignore` → `db/company.sqlite`, `logs/watchdog.json`, `agents/*-LOW-COMPUTE.md`,

runs/metrics that must survive are already mirrored in `logs/runs/*.md` and
`company/metrics.md`. Keep `logs/runs/` and `logs/daily/` tracked — they are the audit trail.
Bound: ≤ 10 lines.
